# Threat Model: Sockeye

## 1. System context

Sockeye is a macOS-first native C++ credential broker for local developer automation. A human stores credentials in macOS Keychain, then approves one explicit session manifest with Touch ID. Sockeye launches the approved child itself, so an AI agent and its subagents never receive raw credentials or a reusable bearer lease.

The first release is intentionally macOS-only. The available Linux and Windows candidates cannot enforce an equivalent biometric policy yet. Code imported from the existing native credential work is treated as material to audit and rewrite, not as a trusted base.

## 2. Assets

| asset                            | description                                                                                           | sensitivity |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------- |
| credential plaintext             | API tokens and application private keys used by local tools.                                          | critical    |
| credential identifiers and scope | Names, child tool, arguments, working directory, and manifest digest reveal and constrain capability. | high        |
| biometric authorization context  | A bounded OS authorization decision valid only for the displayed manifest.                            | critical    |
| child process integrity          | Only the approved executable and invocation may receive credentials.                                  | critical    |
| broker process integrity         | Native memory safety and policy correctness protect all secret-bearing operations.                    | critical    |
| release integrity                | Installed binaries and checksums must correspond to reviewed source.                                  | critical    |

## 3. Entry points & trust boundaries

| entry_point          | description                                                                                                      | trust_boundary                                 | reachable_assets                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------ |
| setup input          | Human-only set/delete and explicit one-time 1Password import accept credential setup input.                      | human terminal → Sockeye                       | credential plaintext, credential identifiers and scope                                     |
| session manifest     | An untrusted parent agent proposes exact credentials, child tool, arguments, bound files, and working directory. | agent process → broker policy parser           | credential identifiers and scope, biometric authorization context, child process integrity |
| macOS Keychain       | Security.framework stores and releases generic-password item data under a biometric ACL.                         | Sockeye process → macOS security services      | credential plaintext, biometric authorization context                                      |
| trusted child launch | Sockeye resolves and launches one approved child and transfers only the manifest-listed credentials.             | broker memory → approved child process         | credential plaintext, child process integrity, broker process integrity                    |
| release artifacts    | GitHub Actions builds and publishes native binaries for installation.                                            | reviewed source and CI → developer workstation | release integrity, broker process integrity                                                |

## 5. Deprioritized

| threat                             | reason                                                                                                          |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Network spoofing                   | The first release has no network listener and no general local socket service.                                  |
| Cross-user IPC                     | The first design launches a trusted child directly and does not expose a reusable machine-wide broker endpoint. |
| Linux and Windows biometric bypass | Those platforms are release-blocked until an equivalent enforced policy is designed and verified.               |
| Remote-agent access                | Remote agents cannot access the developer workstation's local Keychain or Sockeye process.                      |

## 6. Open questions

- Can Sockeye execute the exact inspected file without breaking tools that rely on their executable-relative path?
- Which Agent-CI inputs must use environment variables, and which can move to private inherited file descriptors?
- What minimal audit record is useful without exposing sensitive credential names or task intent?
- Which notarization, hardened-runtime, and release-signing requirements block the first macOS release?
- What evidence would be strong enough to add Linux or Windows without weakening the biometric guarantee?

## 8. Recommended mitigations

| mitigation                                                                                                                                                                       | threat_ids | closes_class | effort |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ------------ | ------ |
| Close the final executable path race with a descriptor-backed or private-snapshot launch that preserves expected runtime behavior.                                               | T4         | yes          | L      |
| Run the complete Keychain policy matrix on clean macOS accounts and verify the displayed approval text.                                                                          | T6,T7,T12  | partial      | M      |
| Fuzz the manifest and terminal parsers, run ASan and UBSan, and add negative tests for malformed UTF-8, NULs, duplicate keys, and oversized fields.                              | T11        | partial      | M      |
| Prefer private inherited file descriptors for child tools that support them; document unavoidable environment exposure for the rest.                                             | T5,T8      | partial      | M      |
| Require reproducible per-platform builds, signed provenance and artifacts, least-privilege release identity, installer checksum verification, and independent bundle validation. | T9         | partial      | L      |
